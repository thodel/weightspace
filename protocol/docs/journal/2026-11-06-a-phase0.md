# 2026-11-06 · Phase 0: harness, practice sets, baselines

**Phase:** 0 · **Budget spent:** none on a real target · **Held-out touched:** no ·
**Source:** `docs/PHASE0_REPORT.md`, commits `c093059`, `7888b01`

## Plan

Verify the harness against kraken 7.0.2, build and audit practice sets, record
the C0/C1 baselines, test the session runner with a no-op smoke session, and
write the first weight readings (zero passes). No budgeted session yet.

## Done

- **Harness and round-trip.** Seven in-house models plus the shared parent
  loaded, re-saved and re-scored: tensor digests equal, text identical,
  CER equal to the last digit. Three corrections to the assumed kraken API,
  one of them a bug: re-saving a CoreML-loaded model writes a model type the
  serving loader refuses; the harness works around it.
- **Sandbox.** Editing programs run in an unprivileged user namespace with
  an empty environment and no network.
- **Practice sets.** 300 lines per family, from the training side only, each
  line list hashed together with the sha256 of every crop. An overlap audit
  against all evaluation documents found every set clean.
- **Baselines** (practice lines, therefore optimistic for the fine-tunes):

  | family | parent CER | best fine-tune CER |
  |---|---:|---:|
  | Bern 1528 (Hertwig) | 0.706 | 0.083 |
  | Kurrent XIX (BLB) | 0.304 | 0.065 |

  Deletions dominate every confusion table.

- **A lossless rewrite** of a kraken+ output head (`Cr255 → Cr1`): 254 of
  255 kernel rows only ever multiply zero padding. Removing them drops
  11,054,080 parameters (15.2 M → 4.2 M) with identical text on all 300
  practice lines and a maximum softmax difference of 1.1 × 10⁻⁶. See
  [Results R1](../results.md#r1).
- **Readings** of five parent→child pairs (rows aligned by character, never by
  index): fine-tuning inflates the output rows of rare characters
  (norm +30–110 %) and barely moves frequent ones; the blank row's bias rises
  in every fine-tune; the first conv block never moves.

## Found

**A data defect explains the worst fine-tune.** A model in the Bern family
(`bern-combined-v1`, held-out 28.8 % CER against its parent's 16.7 %) was
trained from a dataset re-export that pairs 44 of 50 training pages with the
wrong page image (XML identical, images different). The same model reads one
of its own training pages at 96.8 % character accuracy against the earlier
export and 14.3 % against the later one. Its weight profile — blank bias up,
rare rows pushed down hard — is the profile of training on label noise.

A second model family (three from-scratch runs) cannot reproduce its recorded
accuracy because its training material was not archived; it is set aside.

## Changes

- Target 1 is reframed: first a **data** defect, so the honest comparator is

- The defect is to be reported to the dataset owner; it is a finding, not
  fixed in this project.
- First session goes to the Kurrent XIX family (clean data, clean audit).
